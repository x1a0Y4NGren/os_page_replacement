# 页面置换算法说明

负责人：B

本文档记录基础实验中 OPT、FIFO、LRU 三种页面置换算法的接口、实现思路、优缺点和实验结果分析。算法实现位于 `src/algorithms.c`，接口声明位于 `include/algorithms.h`。

## 统一接口

```c
double run_opt(const int pages[], int n, int frame_count);
double run_fifo(const int pages[], int n, int frame_count);
double run_lru(const int pages[], int n, int frame_count);
```

三个函数参数含义一致：

- `pages[]`：页地址流；
- `n`：页地址流长度，本实验为 320；
- `frame_count`：物理内存页框数，范围为 4 到 32；
- 返回值：命中率，即 `hit_count / n`。

算法模块内部使用 `find_page` 查找页面是否已经在内存中，使用 `first_empty_frame` 查找空闲页框。页框数组最大长度为 32，与实验规定的虚拟页数一致。

## OPT 算法

OPT 是最佳页面置换算法。发生缺页且内存已满时，OPT 向后查看未来访问序列，淘汰未来最晚再次访问或以后不再访问的页面。

核心逻辑如下：

```c
for (k = i + 1; k < n; k++) {
    if (pages[k] == frames[j]) {
        next_use = k;
        break;
    }
}

if (next_use > farthest_next_use) {
    farthest_next_use = next_use;
    replace_index = j;
}
```

优点：

- 理论命中率最高，可作为其他算法的性能上限；
- 适合在实验中作为基准算法，衡量 FIFO、LRU 与最优情况的差距。

缺点：

- 需要预知完整的未来访问序列，真实操作系统无法直接实现；
- 模拟时每次缺页都可能向后扫描，计算开销较大。

## FIFO 算法

FIFO 是先进先出页面置换算法。发生缺页且内存已满时，FIFO 淘汰最早进入内存的页面。当前实现通过 `next_replace` 维护循环替换位置。

核心逻辑如下：

```c
frames[next_replace] = page;
next_replace = (next_replace + 1) % frame_count;
```

优点：

- 实现简单，只需要维护一个循环指针；
- 时间开销较低，适合基础模拟和教学实验。

缺点：

- 不考虑页面最近是否被访问；
- 可能淘汰仍然常用的页面；
- 在特定访问序列中可能出现 Belady 异常。

## LRU 算法

LRU 是最近最久未使用页面置换算法。发生缺页且内存已满时，LRU 淘汰最长时间没有被访问的页面。当前实现通过 `last_used[]` 记录每个页框中页面最近一次被访问的位置。

核心逻辑如下：

```c
for (j = 0; j < frame_count; j++) {
    if (last_used[j] < oldest_time) {
        oldest_time = last_used[j];
        replace_index = j;
    }
}
```

优点：

- 利用程序局部性原理，通常比 FIFO 更符合实际访问规律；
- 不需要预知未来访问序列。

缺点：

- 需要维护最近访问时间或访问顺序；
- 精确 LRU 在真实系统中的实现成本较高，常用近似算法替代。

## 性能分析

从页框数变化看，三种算法命中率整体随页框数增加而上升。页框数较少时，内存容量不足，页面换入换出频繁，算法差异更明显；页框数接近 32 时，物理内存基本可以容纳全部虚拟页，三种算法结果趋于一致。

OPT 始终表现最好或并列最好，因为它利用了未来访问信息。FIFO 实现最简单，但不考虑最近访问情况，在低页框数和局部性较弱的场景下性能较弱。LRU 利用最近访问历史，通常更符合程序局部性，但需要额外维护访问时间。

从顺序执行比例看，75% 顺序执行比例下命中率最高，25% 顺序执行比例下命中率最低。顺序访问比例越高，页地址流越集中在相邻页面中，程序局部性越强，页面被再次访问的概率越高。

## 小结

OPT 适合作为理论最优基准；FIFO 简单但稳定性有限；LRU 更符合程序局部性，是实际系统中常用近似算法的重要基础。实验结果表明，页框数和访问局部性是影响命中率的主要因素。
