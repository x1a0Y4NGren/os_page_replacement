# 页面置换算法说明

负责人：B

本文档记录 OPT、FIFO、LRU 三种页面置换算法的原理、接口、优缺点和基础实验性能分析。当前项目中算法代码位于 `src/algorithms.c`，接口声明位于 `include/algorithms.h`。

## 统一接口

```c
double run_opt(const int pages[], int n, int frame_count);
double run_fifo(const int pages[], int n, int frame_count);
double run_lru(const int pages[], int n, int frame_count);
```

三个函数参数含义一致：

- `pages[]`：页地址流；
- `n`：页地址流长度；
- `frame_count`：物理内存页框数；
- 返回值：命中率，即 `hit_count / n`。

## OPT 算法

OPT，即最佳页面置换算法。发生缺页且内存已满时，OPT 会淘汰未来最长时间不会再被访问的页面；如果某个页面之后不再出现，则优先淘汰该页面。

优点：

- 理论命中率最高，可作为 FIFO 和 LRU 的性能上限；
- 适合在实验中作为基准算法，用于评价其他算法与最优情况的差距。

缺点：

- 需要提前知道完整的未来访问序列，真实操作系统无法直接实现；
- 模拟时每次缺页都要向后查找页面下一次出现的位置，计算开销较大。

当前实现方式：遍历页地址流，命中则计数；缺页且有空页框时直接装入；缺页且内存已满时，扫描后续访问序列，选择下一次使用最晚或以后不再使用的页框进行替换。

## FIFO 算法

FIFO，即先进先出页面置换算法。发生缺页且内存已满时，FIFO 淘汰最早进入内存的页面。

优点：

- 实现简单，只需要维护一个循环替换位置；
- 时间开销较低，适合教学实验和基础模拟。

缺点：

- 不考虑页面最近是否被频繁访问；
- 可能淘汰仍然常用的页面；
- 在某些访问序列中可能出现 Belady 异常，即页框数增加但缺页次数反而增加。

当前实现方式：使用 `next_replace` 记录下一次要替换的页框位置。命中时不改变 FIFO 队列顺序；缺页且无空页框时，替换 `next_replace` 指向的页面，然后循环移动该指针。

## LRU 算法

LRU，即最近最久未使用页面置换算法。发生缺页且内存已满时，LRU 淘汰最长时间没有被访问的页面。

优点：

- 利用程序局部性原理，通常比 FIFO 更符合实际访问规律；
- 不需要预知未来访问序列，真实系统中可以通过近似算法实现。

缺点：

- 需要维护页面最近访问时间或访问顺序；
- 精确 LRU 在真实操作系统中维护成本较高。

当前实现方式：使用 `last_used[]` 记录每个页框中页面最近一次被访问的位置。命中时更新访问时间；缺页且内存已满时，选择 `last_used` 最小的页框进行替换。

## 性能分析

从页框数变化看，三种算法的命中率整体都随页框数增加而上升。当页框数较小时，物理内存无法容纳较多页面，缺页更频繁，算法差异更明显；当页框数接近 32 时，物理内存基本可以容纳全部虚拟页，三种算法的命中率趋于一致。

OPT 始终表现最好或并列最好，因为它利用了未来访问序列信息。它不适合作为真实系统中的直接实现，但可以作为实验中的理论上界。FIFO 与 LRU 通常低于 OPT，其中 FIFO 实现最简单，但对最近访问情况不敏感；LRU 利用最近访问历史，在多数情况下比 FIFO 更符合局部性规律。

从顺序执行比例看，75% 顺序执行比例下的命中率整体高于 50% 和 25%。这是因为顺序访问比例越高，页地址流越容易集中在相邻页面中，程序局部性更强，页面被再次访问的概率更高。25% 顺序执行比例下随机跳转更多，局部性较弱，因此低页框数时命中率明显偏低。

## OPT、FIFO、LRU 差距比较

在页框数较少时，OPT 与 FIFO、LRU 的差距最大。例如 25% 顺序比例、Frame 为 4 时，OPT 命中率为 0.5250，而 FIFO 和 LRU 分别为 0.3656 和 0.3719，说明在内存紧张且访问模式较分散时，是否能选择合适的淘汰页面对性能影响很大。

随着顺序执行比例提高，FIFO 和 LRU 与 OPT 的差距缩小。例如 75% 顺序比例、Frame 为 4 时，OPT 为 0.7906，FIFO 为 0.7188，LRU 为 0.7219，三者差距明显小于 25% 顺序比例下的情况。这说明当程序局部性较强时，即使是较简单的 FIFO，也能获得相对较好的命中率。

LRU 与 FIFO 的差距在本实验中并非所有情况下都很大，部分页框数下二者甚至相同。这与当前页地址流的随机生成结果有关。总体上，LRU 由于会保留最近访问过的页面，在局部性明显的序列中更有理论优势；FIFO 则可能因为淘汰顺序固定，在部分访问模式下表现不稳定。

## FIFO 在不同局部性下的表现

在 25% 顺序执行比例下，随机跳转更多，FIFO 的命中率与 OPT 差距较大。这说明 FIFO 缺少对热点页面的识别能力，可能较早淘汰后续仍会被访问的页面。

在 50% 顺序执行比例下，FIFO 的表现有所改善。顺序访问增加后，页面访问更集中，FIFO 的简单替换策略受到的负面影响减小，但整体仍低于 OPT。

在 75% 顺序执行比例下，FIFO 与 LRU、OPT 的差距进一步缩小。由于页面访问更连续，先进先出的替换顺序在很多情况下能够适应访问流，因此命中率明显提高。

## 小结

OPT 是理论最优算法，适合作为性能上界；FIFO 实现简单但稳定性较弱；LRU 综合考虑最近访问历史，更符合程序局部性原理。实验结果表明，页框数增加和顺序执行比例提高都会提升命中率；当页框数足够大时，三种算法最终趋于相同。
