## 指令序列生成

实验共生成 320 条指令，指令地址范围为 `[0, 319]`。

默认实验采用 50% 顺序执行比例，符合实验报告书中的基本要求。扩展对比实验支持 25% 和 75% 顺序执行比例，用于观察程序局部性变化对命中率的影响。

当前实现入口：

```c
void generate_instruction_sequence(int instructions[], int n, double sequential_ratio);
```

检查结论：

- 主程序调用该函数时传入 `INSTRUCTION_COUNT = 320`，能够生成 320 条指令序列。
- 指令地址通过 `clamp_instruction` 限制在 `[0, 319]` 范围内，符合实验中 320 条指令的地址范围要求。
- `sequential_ratio` 会被限制在 `[0.0, 1.0]`，可以支持 25%、50%、75% 顺序执行比例。
- 当前实现使用 `sequential_ratio` 控制顺序访问次数，并将剩余访问分配为前向跳转和后向跳转。该实现能够体现程序局部性和随机跳转特征，但与实验报告书中若采用“固定六步循环”描述的生成过程不一定逐步完全一致，最终报告中建议说明本项目采用的是比例控制式序列生成方法，并与组长确认是否以当前实现为准。

## 页地址流转换

虚存容量为 32 页，每页存放 10 条指令：

```text
page = instruction / 10
```

例如：

- 指令 0 到 9 属于第 0 页。
- 指令 10 到 19 属于第 1 页。
- 指令 310 到 319 属于第 31 页。

当前实现入口：

```c
void convert_to_page_stream(const int instructions[], int pages[], int n);
```

检查结论：当前实现逐条读取指令地址，先将异常地址限制在合法范围内，再执行 `pages[i] = instruction / INSTRUCTIONS_PER_PAGE`。由于 `INSTRUCTIONS_PER_PAGE = 10`，因此页号转换关系就是 `page = instruction / 10`，符合任务要求。

## 实验结论

1. 页框数增加时，三种算法命中率整体呈上升趋势。低 frame 条件下内存容量较小，页面换入换出频繁，因此算法差异更明显；高 frame 条件下可驻留页面更多，缺页次数减少。

2. OPT 命中率通常最高，可以作为理论最优上界。FIFO 和 LRU 不需要预知未来访问序列，更接近实际系统可实现策略，但在低 frame 条件下与 OPT 存在差距。

3. 顺序执行比例越高，程序局部性越强，命中率整体越高。25% 顺序执行比例下随机跳转较多，低 frame 时 FIFO 和 LRU 命中率较低；75% 顺序执行比例下访问更集中，三种算法差距明显缩小。

4. 从同一种算法自身对比看，25%、50%、75% 三种顺序执行比例下的命中率曲线存在明显差异。顺序执行比例越高，访问越集中在相邻页中，页面被再次访问的概率越大，因此 OPT、FIFO、LRU 三种算法各自的命中率都会提高。

5. 综合来看，程序局部性和内存页框数是影响命中率的主要因素。页框数越多、顺序访问比例越高，页面置换算法之间的差异越小；随机性越强、内存越紧张，算法选择对命中率影响越明显。
