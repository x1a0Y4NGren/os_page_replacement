## 指令序列生成

实验共生成 320 条指令，指令地址范围为 `[0, 319]`。当前项目使用比例控制式序列生成方法，通过 `sequential_ratio` 控制顺序执行比例，并将剩余访问分配为前地址访问和后地址访问，以体现程序局部性与随机跳转特征。

接口如下：

```c
void generate_instruction_sequence(int instructions[], int n, double sequential_ratio);
```

当前主程序会分别运行 50%、25%、75% 三组顺序执行比例，其中 50% 是默认基础实验入口，25% 和 75% 用于对比局部性变化对命中率的影响。

## 页地址流转换

实验规定用户虚存容量为 32 页，每页存放 10 条指令。因此页号转换公式为：

```text
page = instruction / 10
```

例如，指令 0 到 9 属于第 0 页，指令 10 到 19 属于第 1 页，指令 310 到 319 属于第 31 页。

接口如下：

```c
void convert_to_page_stream(const int instructions[], int pages[], int n);
```

当前实现会先将异常指令地址限制在合法范围内，再执行 `pages[i] = instruction / INSTRUCTIONS_PER_PAGE`。由于 `INSTRUCTIONS_PER_PAGE = 10`，转换结果与实验要求一致。

## 实验结论

1. 页框数增加时，OPT、FIFO、LRU 三种算法命中率整体提高。
2. OPT 通常最高，可作为理论最优上界。
3. FIFO 实现简单，但在局部性较弱和页框数较少时性能较弱。
4. LRU 利用最近访问历史，通常比 FIFO 更符合程序局部性。
5. 顺序执行比例越高，页地址流局部性越强，三种算法命中率整体越高。

综合来看，内存页框数和访问局部性是影响页面置换命中率的主要因素。实验结果符合请求页式虚拟存储管理中关于程序局部性和页面置换策略的基本理论。
