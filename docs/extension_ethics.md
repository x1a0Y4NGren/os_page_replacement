本文档记录随机页地址流、循环页地址流、CLOCK / Second Chance 改进算法实验，以及页面置换算法选择中的科技伦理思考。扩展代码位于 `src/extension.c`，接口声明位于 `include/extension.h`。

## 扩展接口

当前扩展模块提供以下接口：

```c
void generate_random_page_stream(int pages[], int n);
void generate_loop_page_stream(int pages[], int n);
double run_improved_algorithm(const int pages[], int n, int frame_count);
void run_extension_experiments(void);
```

其中 `run_improved_algorithm` 已实现为 CLOCK / Second Chance 页面置换算法，返回值为命中率，便于与 OPT、FIFO、LRU 统一比较。`run_extension_experiments` 会在主程序中被调用，默认输出随机序列和循环序列两组扩展实验结果。

## 随机页地址流实验

随机页地址流在 0 到 31 页之间均匀取值，用于模拟局部性较弱、访问模式较难预测的场景。该序列没有明显时间局部性或空间局部性，因此算法差异主要来自页面替换策略本身。

实验结果节选如下，完整结果见 `results/linux_make_run.txt`。

| Frame | OPT | FIFO | LRU | CLOCK |
| --- | --- | --- | --- | --- |
| 4 | 0.3406 | 0.1219 | 0.1375 | 0.1281 |
| 8 | 0.5406 | 0.2469 | 0.2562 | 0.2625 |
| 12 | 0.6500 | 0.3656 | 0.3875 | 0.3906 |
| 16 | 0.7250 | 0.5250 | 0.5031 | 0.5156 |
| 20 | 0.7875 | 0.5906 | 0.6156 | 0.6312 |
| 24 | 0.8406 | 0.7094 | 0.7094 | 0.7188 |
| 28 | 0.8812 | 0.8250 | 0.8063 | 0.8063 |
| 32 | 0.9000 | 0.9000 | 0.9000 | 0.9000 |

随机序列下，OPT 仍然是理论上界。FIFO 在低页框数时命中率最低；LRU 和 CLOCK 利用了最近访问信息或引用位信息，通常比 FIFO 更稳定。当页框数增加到接近 32 时，四种算法都趋于一致。

## 循环页地址流实验

循环页地址流采用固定工作集：

```text
0, 1, 2, 3, 4, 5, 2, 3
```

该序列用于模拟循环结构、热点数据集或重复请求场景。由于工作集规模较小，当 frame 数不足以容纳工作集时，缺页较频繁；当 frame 数达到或超过工作集规模后，后续访问基本都能命中。

实验结果节选如下：

| Frame | OPT | FIFO | LRU | CLOCK |
| --- | --- | --- | --- | --- |
| 4 | 0.6562 | 0.2500 | 0.4938 | 0.2500 |
| 5 | 0.8187 | 0.2500 | 0.4938 | 0.3719 |
| 6 | 0.9812 | 0.9812 | 0.9812 | 0.9812 |
| 8 | 0.9812 | 0.9812 | 0.9812 | 0.9812 |
| 12 | 0.9812 | 0.9812 | 0.9812 | 0.9812 |
| 16 | 0.9812 | 0.9812 | 0.9812 | 0.9812 |
| 24 | 0.9812 | 0.9812 | 0.9812 | 0.9812 |
| 32 | 0.9812 | 0.9812 | 0.9812 | 0.9812 |

循环序列中 frame 为 4 或 5 时算法差异明显。OPT 能利用未来访问信息选择更合适的淘汰页；LRU 能保留最近频繁访问的页面，通常优于 FIFO；CLOCK 在该序列中可能接近 FIFO。当 frame 达到 6 后，内存已经能够容纳循环工作集，各算法命中率迅速提高到 0.9812。

## CLOCK 改进算法

CLOCK 算法也称 Second Chance 算法，是对 FIFO 的改进。它为每个页框维护一个引用位：

- 页面被访问时，将引用位置为 1；
- 发生缺页且需要替换时，时钟指针循环扫描页框；
- 如果当前页框引用位为 1，则清零并给予第二次机会；
- 如果当前页框引用位为 0，或页框为空，则替换该页框。

核心逻辑如下：

```c
while (1) {
    if (frames[hand] == -1 || reference_bits[hand] == 0) {
        frames[hand] = page;
        reference_bits[hand] = 1;
        hand = (hand + 1) % frame_count;
        break;
    }

    reference_bits[hand] = 0;
    hand = (hand + 1) % frame_count;
}
```

CLOCK 的优点是实现简单、开销较低，不需要像精确 LRU 一样维护完整访问顺序，同时又比纯 FIFO 多利用了“最近是否被访问”的信息。其局限是引用位只能提供粗粒度信息，不能准确区分访问频率和访问时间远近；当大量页面引用位都为 1 时，CLOCK 可能退化得接近 FIFO。

## 扩展实验结论

1. 随机序列局部性较弱，低页框数下命中率较低，算法差异明显。
2. 循环序列具有稳定工作集，只要 frame 数能够容纳工作集，命中率会快速升高。
3. CLOCK 在实现成本和命中率之间取得折中，通常比 FIFO 更适合真实系统中的低开销页面置换。
4. OPT 只能作为理论最优基准，真实系统更常采用 LRU 近似算法或 CLOCK 类算法。

## 科技伦理思考

页面置换算法虽然属于操作系统底层策略，但在 Web 服务器、云平台和多租户环境中会影响系统稳定性、资源公平性和用户体验。

首先，算法选择会影响服务稳定性。Web 服务器在高并发请求下如果频繁缺页，请求延迟会增加，严重时可能导致服务质量下降。因此系统设计者不能只关注平均命中率，还应关注内存压力较大时的尾延迟和稳定性。

其次，算法选择涉及资源公平。多进程或多租户环境中，内存不足时页面置换会影响不同应用的运行表现。如果某些访问模式长期占用更多内存，其他任务可能频繁缺页，从而造成资源分配不公平。因此页面置换策略应与工作集控制、配额管理等机制结合使用。

再次，实验结论需要保持透明和可解释。本项目发布到 GitHub 时，应明确说明实验条件、随机序列生成方式和算法限制，避免将教学模拟结果直接等同于生产系统结论。

最后，资源效率也具有伦理意义。较高的命中率可以减少磁盘交换和无效等待，降低能耗并提升用户体验。合理选择页面置换算法不仅是性能优化问题，也体现了对计算资源、用户时间和系统可靠性的负责。
