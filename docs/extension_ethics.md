## 扩展接口

当前扩展模块提供以下接口：

```c
void generate_random_page_stream(int pages[], int n);
void generate_loop_page_stream(int pages[], int n);
double run_improved_algorithm(const int pages[], int n, int frame_count);
void run_extension_experiments(void);
```

其中 `run_improved_algorithm` 当前实现为 CLOCK / Second Chance 页面置换算法，返回值为命中率，便于和 OPT、FIFO、LRU 统一比较。

## 随机序列实验

随机序列在 0 到 31 页之间均匀取值，用于模拟局部性较弱、访问模式较难预测的场景。该序列下页面访问没有明显时间局部性或空间局部性，因此不同算法之间的差异主要来自页面替换策略本身。

程序会输出 frame 4 到 32 下 OPT、FIFO、LRU、CLOCK 四种算法的命中率。总体趋势是：随着 frame 数增加，命中率逐步上升；当 frame 接近 32 时，物理内存可以容纳全部虚拟页，四种算法结果趋于一致。

随机序列下，OPT 仍然作为理论上界；FIFO 通常表现较弱；CLOCK 通过引用位保留最近被访问过的页面，在实现开销较低的前提下通常比 FIFO 更稳健，表现接近 LRU。

## 循环序列实验

循环序列采用固定工作集：

```text
0, 1, 2, 3, 4, 5, 2, 3
```

该序列用于模拟循环结构、热点数据集或重复请求场景。由于循环工作集规模较小，当 frame 数不足以容纳工作集时，缺页会比较频繁；当 frame 数可以容纳工作集后，后续访问基本都能命中。

实验结果中，frame 为 4 时不同算法差异明显。OPT 能利用未来访问信息选择更合适的淘汰页；LRU 能利用最近访问历史，通常优于 FIFO；CLOCK 在该场景下可能与 FIFO 接近。当 frame 达到或超过工作集规模后，各算法命中率都快速接近较高水平。

## CLOCK 改进算法

CLOCK 算法也称 Second Chance 算法，是对 FIFO 的改进。它为每个页框维护一个引用位：

- 页面被访问时，引用位置为 1；
- 发生缺页且需要替换时，时钟指针循环扫描页框；
- 如果当前页框引用位为 1，则清零并给它第二次机会；
- 如果当前页框引用位为 0，则替换该页框。

CLOCK 的优点是实现简单，开销低，不需要像精确 LRU 一样维护完整访问顺序；同时它又能保留“最近是否被访问过”的信息，因此在实际系统中比纯 FIFO 更实用。

CLOCK 的局限在于：它只能区分页面最近是否被访问，不能准确区分访问频率和访问时间远近。当大量页面引用位都为 1 时，CLOCK 可能退化得接近 FIFO。在内存严重不足、工作集无法装入内存时，CLOCK 也无法从根本上避免频繁缺页。

## 扩展实验结论

1. 随机序列缺少明显局部性，页框数对命中率影响明显，算法差异在低 frame 时更突出。
2. 循环序列具有稳定工作集，只要 frame 数足够容纳工作集，命中率会快速提高。
3. CLOCK 在实现复杂度和运行效果之间取得折中，比 FIFO 多利用了引用位信息，通常比 FIFO 更适合真实系统。
4. OPT 仍然只能作为理论比较标准，真实系统中更常采用 LRU 近似算法或 CLOCK 这类低开销策略。

## 科技伦理思考

页面置换算法虽然属于操作系统底层策略，但在 Web 服务器、云平台和多租户环境中会影响系统稳定性、资源公平性和用户体验。

首先，算法选择会影响服务稳定性。Web 服务器在高并发请求下如果频繁缺页，请求延迟会明显增加，严重时可能造成服务质量下降。系统设计者不能只追求平均命中率，还要关注极端情况下的尾延迟和稳定性。

其次，算法选择涉及资源公平。多进程或多租户环境中，内存不足时页面置换会影响不同应用的运行表现。如果某些访问模式长期占用更多内存，而其他任务频繁缺页，就会造成资源分配不公平。因此页面置换策略应与工作集控制、配额管理等机制结合使用。

再次，算法实现需要考虑透明性和可解释性。教学实验中的数据不能直接等同于生产系统结论。将项目发布到 GitHub 时，应说明实验条件、随机序列生成方式和算法限制，避免误导他人将模拟结果直接用于真实系统决策。

最后，资源效率也具有伦理意义。较高的命中率可以减少磁盘交换和无效等待，降低能耗并提升用户体验。合理选择页面置换算法不仅是性能优化问题，也体现了对计算资源、用户时间和系统可靠性的负责。
